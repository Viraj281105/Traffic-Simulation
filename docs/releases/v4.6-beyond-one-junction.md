# UrbanFlow V4.6 - Beyond One Junction: release note and G-REL2 evidence

Branch `viraj-dev`. Release week W46 (plan dates Feb 15 - Feb 19, 2027; the code was written ahead of those dates). This page maps each gate criterion of **G-REL2** to evidence and states plainly what was run and what was only written. The claims it permits are in [claims-register-v4.6.md](claims-register-v4.6.md). The previous release page is [../v3-release-candidate.md](../v3-release-candidate.md).

Status words (same as `docs/operations-observability.md`):

* **VERIFIED**: run in the development environment; a test or command is named and passed.
* **WRITTEN**: authored with care, but the tool, cluster or data needed to run it is not available here. Not run.
* **NEEDS-INPUT**: blocked on a decision, dataset or account that only the project owner can supply.

## G-REL2 gate

Gate text (WEEKLY_PLAN W46): real network of 10+ junctions, calibration error reported, RL compared with baselines, dashboards and SLOs live.

| Criterion | Status | What is true |
| --- | --- | --- |
| Real network of 10+ junctions | **VERIFIED for a 12-junction synthetic grid; not a real city** | The 3 x 4 network of 12 signalised junctions runs end to end with vehicle conservation. It is a generated grid anchored to a London lat/lon so a map can place it; it is not OpenStreetMap data of a real district. Real-network import code exists (ADR-021) but no real network was run through the simulator and calibrated. |
| Calibration error reported | **VERIFIED on synthetic ground truth only; real dataset NEEDS-INPUT** | The pipeline produces a report with GEH, RMSE, MAPE and the G-CAL verdict, before and after. The "observed" counts were generated by the simulator itself from known multipliers, so a pass shows the optimiser recovers a known answer, not that the model matches a real road. |
| RL compared with baselines | **Machinery VERIFIED; no real training result** | Multi-junction environment, fixed-time and max-pressure baselines, paired-CI evaluation, model registry and retraining stages are tested at smoke budgets. No long-budget training run was done, so there is no trained-policy-beats-baseline number to cite. |
| Dashboards and SLOs live | **WRITTEN, not run** | SLO file, evaluator, metrics endpoint and alert rules exist and the evaluator and endpoint are tested. Prometheus and Grafana were never started; nothing is "live". |

G-REL2 is therefore **not met as worded**. What is met is the code, the tests and the honest limits. The two blockers are owner decisions (a real count dataset and network, D1) and compute time (RL training budget).

### 6. Reproducibility audit

Command: `cd backend && .venv/Scripts/python ../scripts/reproducibility_audit.py` (add `--quick` for tiny durations); test: `backend/tests/audit/test_reproducibility_audit.py`.

The script runs a multi-seed signal study, the 12-junction network metrics and a synthetic calibration, each twice with fixed seeds, compares canonical JSON (timestamps removed) and checks run-manifest hashes. Result when run for this release:

| Scenario | Run A = Run B | Manifest hash |
| --- | --- | --- |
| Multi-seed study (signal), 2 seeds, 20 s | identical | full SHA-256, matches a fresh hash of the config |
| 12-junction network metrics, 120 s, seed 7 | identical | none recorded |
| Network calibration (synthetic), budget 6 | identical | full SHA-256 (report manifest) |

**No nondeterminism was found.** Limits of this check: both runs are in one process on one machine, one Python version and one commit. It does not show cross-machine or cross-version equality, covers three small scenarios and not the whole product, and the network-metrics output carries no manifest of its own.

## Known gaps and fix list

| # | Gap | Impact | Fix | Owner input |
| --- | --- | --- | --- | --- |
| 1 | No real city network or counts | G-REL2 first two criteria not met in the real sense | Choose dataset and city (D1); import OSM, load counts, run `scripts/calibrate_network.py`, report the actual GEH/MAPE | yes |
| 2 | No long-budget RL result | Cannot claim RL beats baselines | Run `scripts/rl_network_evaluate.py` with a long training budget; publish the result file and paired CIs, including if RL loses | compute time |
| 3 | Dashboards and SLOs never run | "Live" cannot be claimed | Start `deploy/observability/docker-compose.yml`, run `promtool check`, load k6, record findings in `docs/operations-observability.md` section 8 | Docker, k6 |
| 4 | Run counters not wired at launch points | Run SLOs report `no_data` | Call `METRICS.track_run(...)` and `set_queue_depth(...)` where runs launch | none |
| 5 | Go consumer, k6, Redpanda, Helm, kind never executed | Unknown whether they work | Run `go mod tidy && go test ./...`, `helm lint`, `kind create cluster` | tooling |
| 6 | `prometheus_client` and OTel SDK paths untested | Two optional paths skip | Install the packages in a CI job | none |
| 7 | Synthetic grid is symmetric and uses mesoscopic links | Congestion results may not transfer to real roads | State as a limitation (done here); validate on a real network | yes |
| 8 | Audit covers repeatability in one process only | No cross-machine claim | Run the audit in CI on two runners and compare hashes | none |
| 9 | `gitDirty` in manifests is always `unknown` | A run may include uncommitted edits | Record the working-tree state at run time | none |
| 10 | Live traffic feed source undecided (D3) | W51 adapter blocked | Decide in W46 | yes |

## Reading this release

The accurate sentence for this release is: UrbanFlow V4.6 simulates, measures, calibrates and controls a 12-junction synthetic network in code that is tested locally, with the observability and deployment configuration written but not run. It does not claim a calibrated model of a real city or a trained controller that beats baselines.
